# PureGamma AI v0.2.2

Release train: **v0.2.2**  
Baseline: **v0.2.1 → main**  
Delivery assets: source archive, Android APK, iOS unsigned IPA.

## Highlights

### Agent, Harness, and research
- Expanded the PureGamma Harness plugin runtime and retained the DeepSeek Harness
  reference integration while keeping business capabilities behind explicit
  capability boundaries.
- Added the Dream-RSI strategy-family control plane across Momentum, VWAP,
  Orderflow, Funding + OI, Mean Reversion, and Hybrid families.
- Added chronological IS/OOS evaluation, replayable discovery trees, bounded
  family-level compute reallocation, and explicit insufficient-history
  degradation.
- Added persisted Agent run events, stronger reconnect behavior, research run
  surfaces, evidence snapshots, and user-owned memory controls.
- Added JEV advisory/decision surfaces and preserved the read-only/research
  boundary between model decisions and order execution.

### Portfolio, PM NAV, and trading safety
- Expanded server-computed NAV and portfolio views, including the restricted
  Binance Portfolio Margin riskbot bundle used by authorized accounts.
- Added trading mandates, risk checks, kill switches, immutable ledger entries,
  reconciliation, UNKNOWN submit-timeout handling, and explicit LIVE-disabled
  states.
- Preserved the rule that research, Agent, Dream-RSI, and legacy Nautilus paths
  cannot bypass the dedicated LIVE trading control plane.
- Improved restart/recovery and production deployment boundaries for the
  Nautilus runtime.
- Reconciliation rejects missing, NaN, infinite, or malformed monetary values
  instead of coercing them to zero; lost position observability pauses LIVE
  mandates.
- Scheduler stale-lock recovery is explicitly observable rather than silently
  reacquiring the scheduler lease.

### Data, news, and evidence quality
- Added ChainCatcher Market Wire ingestion and normalized news/evidence flows.
- Expanded public/portfolio data adapters and explicit freshness, entitlement,
  provenance, and stale-state handling.
- Removed legacy compatibility behavior that returned fixed CoinGecko,
  CoinGlass, Glassnode, macro, Reddit, or X sentiment values. Unreviewed legacy
  facades now fail closed instead of fabricating successful market evidence.

### Billing, API gateway, and delivery
- Expanded subscription entitlements, credit accounting, gateway wallet
  accounting, pricing approvals, and OpenAI-compatible gateway controls.
- Hardened Stripe refund/top-up accounting and notification/daily-brief flows.
- Stripe webhook verification errors are redacted; internal post-verification
  failures return retryable server errors instead of being mislabeled as bad
  client requests.
- Notification mock recipients are never marked delivered or billed, and
  provider exceptions persist an auditable failed delivery after credit refund.
- Expanded iMessage/Photon, Telegram, push, and mobile handoff functionality.

### Web, Android, and iOS
- Expanded the Glass web product experience, appearance controls, Agent UI,
  research, news, memory, PM NAV, JEV, and trading safety surfaces.
- Continued Android Compose/WebView and SwiftUI capability-gated clients with
  fail-honest unavailable states instead of fake data.
- The GitHub v0.2.2 release workflow builds exactly three release assets:
  1. `puregamma-v0.2.2-src.tar.gz`
  2. Android installable APK using the current Android app version
  3. iOS unsigned IPA using the current iOS app version

## Commercial deployment hardening

This release adds or tightens production release gates:

- production environment validation is fail-closed;
- deployment only proceeds from a clean canonical `main` checkout;
- backups, application config validation, migrations, and readiness are hard
  release gates;
- Redis authentication, strong runtime/session/encryption secrets, HTTPS
  callbacks, exact CORS origins, and a private metrics bearer token are validated;
- `/metrics` is protected in production and serves Prometheus text;
- commercial CI checks fatal Python defects, backend regression/security tests,
  web typecheck/lint/build, marketing-site tests, production Compose config,
  and rollback-script safety contracts;
- pnpm is pinned and the web workspace is explicit so hosted-runner builds are
  reproducible;
- rollback captures a rescue pin from the actually running containers, validates
  target images/Compose before cutover, verifies API/Web health after cutover,
  and attempts to restore the rescue pins if verification fails;
- the GitHub release workflow cannot publish from a commit lacking exact-SHA
  green evidence from both commercial gates.

## Release policy

v0.2.2 is a source/product release, not an assertion that every optional
provider or LIVE execution capability is enabled in production. Optional
providers, Harness network access, Memory rollout, broker connectivity, and LIVE
trading remain controlled by environment flags, entitlement policy, explicit
approvals, health checks, and deployment runbooks.

## Publish gate

The release should only be triggered after both workflows are green on the
target `main` commit:

- `PureGamma commercial readiness`
- `PureGamma Commercial Release Gate`

The `Mobile Release Build` workflow is then dispatched for `v0.2.2` (or
triggered by the release tag). Its prepare job independently queries GitHub for
successful runs of both commercial workflows on the **exact target commit** and
refuses to publish if either proof is missing. It then builds and publishes the
three release assets to GitHub Releases.
